# 계정 관심 지역 동기화 설정

## 인증 서명 키

백엔드 실행 환경에 `AUTH_SECRET_KEY`를 설정해야 로그인 토큰을 발급할 수 있습니다. 최소 32자 이상의 예측 불가능한 값을 사용하고, 프런트엔드나 Git 저장소에 실제 값을 넣지 마세요.

PowerShell에서 키를 만들려면 다음 명령을 실행하고, 출력된 값은 백엔드의 환경 변수 설정에 직접 등록합니다.

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

배포 환경에서는 Render의 백엔드 서비스 환경 변수에 `AUTH_SECRET_KEY`를 등록한 뒤 재배포해야 합니다. 키를 교체하면 기존 로그인 토큰은 만료 처리되어 사용자가 다시 로그인해야 합니다.

## DB 테이블

인증된 사용자의 관심 지역은 `user_favorites` 테이블에 저장됩니다. 애플리케이션은 관심 지역 API가 처음 호출될 때 테이블을 `CREATE TABLE IF NOT EXISTS`로 준비합니다. 운영 DB 계정에 테이블 생성 권한을 주지 않는 경우에는 `migrations/001_user_favorites.sql`을 DB에 한 번 적용하세요.

각 관심 지역은 사용자 ID, 이름, 위도·경도, 정렬 순서로 저장되며 사용자당 최대 5곳입니다. 계정 삭제 시 외래 키의 `ON DELETE CASCADE`로 해당 관심 지역도 삭제됩니다.
